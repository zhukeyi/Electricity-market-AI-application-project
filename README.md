## 1 结论先行

本方案的核心判断只有四条，其余全部是它的推论：

1. **这不是预测题，是「排序题 + 正确性考题」。**
   价格公开、模型能力趋同，全市场的预测差距被压缩进 **4.9%** 的带宽（完美预见 100% vs persistence ≈95%）；而**一天提交失败或越限 = −7.1%**（1/14），一次重度亏损日 = −8.3%。任何一次工程事故都大于「把预测做到完美」的全部收益。

2. **可行性是二元的，收益是连续的。**
   手册规定「任一时段越限 → 当日全天 Q=0」。没有中间态，没有罚分。因此工程重心必须压在「绝不越限」，而不是继续调模型。

3. **稳的是可行性，不是收益。**
   正确姿势是两端同时极端：物理上极端保守（5 道防线），经济上极端激进（满充满放、不做任何过滤、不缩量）。最优解本来就贴着边界——官方示例的充电段精确停在距 SOC 上限 0.003 MWh 处。

4. **真正的风险不是「某天亏」，而是「连续失败」。**
   唯一的跨日状态通道是 SOC 链（次日 SOC₀ = 当日 SOC₂₄）。任何让 SOC 链断掉或漂移的缺陷，都会从那天起**每天**归零。风险管理的第一优先级是切断故障的跨日传播。

## 4 快速开始

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

export PYTHONPATH=.
.venv/bin/python -m unittest discover -s tests -t .    # 95 项测试
.venv/bin/python scripts/rehearse.py --days 14          # 14 天全链路彩排
.venv/bin/python scripts/pipeline.py --check-data       # 数据体检
```

每日生产运行（无人值守）走 `scripts/daily.sh`，由 `deploy/csg-pipeline.timer` 在 **BJ 23:00** 触发。详见 [`docs/04-工程实现.md`](docs/04-工程实现.md)。
