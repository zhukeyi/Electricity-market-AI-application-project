| 参数 | 符号 | 取值 | 换算 |
|---|---|---|---|
| 储能额定容量 | Q_base | **14 MWh** | — |
| 最大充放电功率 | P_max | **7 MW** | 每小时 |

## 2 申报内容：24 时段自调度曲线

提交运行日 **24 个时段**的日前充放电曲线 `Q_DA,battery`：

- **正数 = 放电**，**负数 = 充电**，**0 = 不动作**
- 单位 MW，保留**两位小数**
- 时段为整点小时，24 段覆盖运行日 00:00–24:00（加州时间）

### 2.1 功率约束

```
−P_max ≤ Q_{d,t}^DA,battery ≤ P_max
```

即每个时段落在 **[−7, +7] MW**。

### 2.2 电量连续约束（SOC 递推）

```
充电（Q ≤ 0）：SOC_{t+1} = SOC_t − (Q / Q_base) · η
放电（Q > 0）：SOC_{t+1} = SOC_t − Q / (Q_base · η)
```

中文读法：**充进去的只有 η 部分入库；放出来的要从库里多抽 1/η。**

注意两条公式的符号不对称——充电时 Q 为负，`−(Q/Q_base)·η` 为正（SOC 上升）；放电时 Q 为正，`−Q/(Q_base·η)` 为负（SOC 下降）。

### 2.3 荷电状态约束

```
SOC̲ ≤ SOC_{t+1} ≤ SOC̄        即 5% ≤ SOC ≤ 95%
```

**约束作用在 SOC_{t+1}（时段末状态），t 从 1 到 24**，共 24 个约束点。初始状态 SOC₁ = SOC₀ 受约束但由前一日决定。

### 2.4 平台校验方式

> 「比赛平台将从当日初始 SOC₀ 出发，根据参赛算法提交的 Q 进行上述约束判断。」（PDF 14）

## 3 越限后果：二元、无中间态

> 「1) 若日前自调度曲线满足上述全部约束，则该日前计划有效，储能实际调度按计划进行，Q_RT = Q_DA；
> 2) **若任何一时段不满足，则判定当日日前自调度申报失败，当日全天储能实际调度视为不充电、不放电，Q_RT,battery = 0**。」（PDF 15）

三个必须理解的点：

1. **一个时段越界，整天 24 个时段的有效动作全部作废。** 不是罚分，不是部分生效。
2. **越限与漏交后果完全相同**——都是当日 `R = 0`。所以「保证物理可行」的价值不在于「避免 0 分」，而在于「避免从正值掉到 0」。
3. **SOC 是累积量，逐点都合规 ≠ 轨迹合规。** 必须整条 24 点轨迹每一格都在 `[5%, 95%]` 内。

### 3.1 跨日耦合

> 「下一日储能的初始 SOC₀ 为前一日的末状态 SOC₂₄。」（PDF 15）

这是全赛制**唯一的跨日状态通道**，也是故障传播的唯一路径。

一旦某日提交的曲线使 SOC₂₄ 落在某个值，次日的可行域就被这个值锁定了。若实现中有任何 bug 导致 SOC₂₄ 算错，错误会**每天累积**，从某天起每天都不再可行。

## 4 收益结算

> 「d−1 日 24:00 前，比赛平台按照如下公式进行收益结算。」（PDF 23）

```
R_d^battery = Σ_{t=1}^{24} p_{d,t}^DA · Q_{d,t}^DA,battery
```

| 符号 | 含义 |
|---|---|
| p^DA | 日前市场 t 时段出清价格，CAISO SP15，`TH_SP15_GEN-APND`，DAM，LMP |
| Q^DA | 本队申报的 t 时段充放电功率 |

单位换算：MW × $/MWh × 1h = $。

**线上组没有**：实时市场结算、30% 偏差回收 `C^load`。后者是线下组售电公司代理负荷的条款。

## 5 评分规则

### 5.1 单日得分

```
s_d = min{ 100, max[ 0, 60 + s₄ · (R_d − μ) / σ ] }
```

| 符号 | 含义 |
|---|---|
| R_d | 本队当日单日收益 |
| μ | **本组本赛道全部参赛者**当日收益的均值 |
| σ | 同上，标准差 |
| s₄ | 评分参数，**取 10**（PDF 23 明确给出） |

解读：

- 收益 = 均值 → **60 分**
- 高于均值一个标准差 → **70 分**
- 低于均值一个标准差 → **50 分**
- 上下分别截断在 **100 / 0**

### 5.2 总分

```
S = (1/D) · Σ_{d=1}^{D} s_d ，D = 14
```

有效比赛日得分的**算术平均**。

### 5.3 排名与同分规则（PDF 24）

1. 按 S 由大到小排序得排名。
2. **若最终评分均为 100**：改按 `max[0, 60 + s₄(R−μ)/σ]` 的 14 天均值降序——即**去掉 100 上限**。
3. **若最终评分均为 0**：改按 `60 + s₄(R−μ)/σ` 的 14 天均值降序——即**去掉 0 下限**。

**推论：顶格 100 不是终点。** 这条规则说明主办方预期会有批量队伍顶格，真正的区分发生在超额收益上。

### 5.4 相对评分的两个反直觉含义

| 直觉 | 实际 |
|---|---|
| 「收益为负就是坏事」 | **错**。若当日全市场都亏（μ<0），我方亏得少则 `R−μ>0`，照样得 60 分以上 |
| 「收益为正就是好事」 | **错**。赚钱的日子若赚得比别人少，分数会低于 60 |

所以真正的目标是**每天都把 R 做到自己能力的上界**，而不是追求账面上不出现负数。这直接否定了「避免亏损日」这类目标，也是「预测收益门槛」策略必然亏本的深层原因（详见 `03-策略与思路.md` §4.2）。

## 7 提交文件规格（由官方模板反解 + 字节级核验）

官方 V3.0 只提供 xlsx。以下规格由解析模板并与导出的 CSV 逐字节比对得到。

### 7.1 六个字段

```
序号, OPR_DT, OPR_HR, INTERVALSTARTTIME_GMT, INTERVALENDTIME_GMT, storage_power_mw
```

24 行数据 + 1 行标题 + 1 行说明。

### 7.2 四个易错点

| 项目 | 规格 | 常见错误 |
|---|---|---|
| `OPR_HR` | **1 – 24**（1-based） | 旧版 `skd` 是 0-based 的 `H:00:00`，偏移会整体错位 |
| `OPR_DT` | `yyyy/m/d`，**月日不补零** | 写成 `2026/12/06` 不符合模板（应为 `2026/12/6`） |
| GMT 偏移 | 字面量恒为 **`-00:00`** | 写成 `+00:00` 或 `Z` 不匹配 |
| 跨日 | **HR17 起 GMT 日期已进入次日，而 `OPR_DT` 不变** | 按 GMT 日期分组会拆断当日 |

### 7.3 字节层面

| 项目 | 实测值 |
|---|---|
| 编码 | UTF-8 无文件头 BOM |
| 表头第二列前 | 有 `EF BB BF`（BOM 出现在字段内部，不在文件头） |
| 行分隔 | CRLF（`\r\n`），共 27 处（26 行 + 末行） |
| 说明行内部 | 3 处裸 LF（说明文字内部换行） |
| 数值格式 | 两位小数，如 `-0.01`、`6.99`、`0.00` |
| 标题 | `（线上组）队名 (团队成员甲\乙)——交易决策结果`，成员间用**反斜杠** |

> ⚠ V3.0 只发布 xlsx，**导出 CSV 后的真实字节（BOM/CRLF）尚无平台回执**。首日提交前需人工试传一次。

## 8 官方示例曲线为什么不可行

官方模板自带一条示例曲线，看起来像可以直接照抄的起点。**实测它不可行。**

示例值：HR12 = −7、HR13 = −7、HR14 = −0.82、HR17/18/19 = +10、HR22/23 = −7。

按 14 MWh / 7 MW / η=0.85 逐时段重放：

```
HR   Q(MW)   SOC_end(MWh)   SOC%
12   -7.00        6.650     47.50%     ← 充电，SOC 上升
13   -7.00       12.600     90.00%
14   -0.82       13.297     94.98%     ← 距上限 13.300 仅 0.003 MWh
...
17   +10.00       5.297     37.84%     ← 超 Pmax=7
18   +10.00      -2.703    -19.31%     ← 破下限
19   +10.00     -10.703    -76.45%
...
越限时段：17,18,19,20,21,22,23,24
```

两个问题叠加：

1. **功率越限**：+10 MW 超过 Pmax = 7 MW。
2. **能量不足**：即使把放电钳到 7 MW，SOC 仍会穿底至负值。

**照抄这条示例 = 当日全天收益归零。**

### 8.1 但它的充电段是精确的

注意 HR14 末态 **13.297 MWh**，距 95% 上限 13.300 只有 **0.003 MWh**。

这不是随手写的数字。它证明模板作者**确实按 14 MWh / 7 MW / η=0.85 反解过 SOC 轨迹**，只是放电段填了占位值。

这条观察有两个用处：

1. 确认了我们的资产参数与符号约定（正放负充）**与官方一致**。
2. 确认了**最优解本来就贴着边界**——离上限 0.003 MWh，不是「保守留余量」。这直接支持了策略上的「可行域边界行走」原则（见 `03-策略与思路.md` §3）。
